# Frappe 讲义：核心理念与架构解析（基础友好详解版）

这份讲义不追求一开始就讲得很“架构师”。它会先用具体业务例子解释概念，再逐步说明背后的技术含义。阅读时可以一直带着一个问题：如果我是企业里的工程师、经理或实施顾问，我希望系统帮我解决什么问题？

## 第一阶段：破冰与思维范式的颠覆 (The Mindset Shift)

### 1. 从 SQL-Centric 到 Meta-driven (元数据驱动)
在传统 ERP 开发中，数据库 Schema 是地基，所有上层建筑（Model, Controller, View）都随之摆动。
*   **Frappe 的演进：** 通过 `DocType`（文档类型）这一元数据层，将底层的数据库操作与上层的 UI 渲染解耦。
*   **技术边界：** 虽然 Frappe 自动处理了 90% 的数据库同步，但在涉及海量数据迁移、复杂索引优化或跨库操作时，开发者仍需通过 `frappe.db` 甚至原生 SQL 进行干预。请记住，自动化不是魔法，理解底层的 MariaDB 实现依然重要。

**具体例子：**

传统做法中，如果要给“物料”增加一个“规格”字段，开发者通常要改数据库、后端模型、接口、前端页面和权限。Frappe 中，你在 `P-Item` 这个 DocType 上增加 `specification` 字段后，表单、列表、接口和数据库字段会围绕这份元数据自动工作。

**初学者理解方式：**

可以把 DocType 想象成一张“系统蓝图”。你告诉 Frappe 这张业务表单有哪些字段、字段是什么类型、是否必填、是否引用别的数据。Frappe 根据蓝图生成页面和数据结构。

### 2. Batteries Included (自带电池) 的开发哲学
Frappe 提供了极高的开箱即用能力。
*   **低代码完成标准 CRUD：** 框架自动生成的 REST API 和 Web UI 能满足绝大多数标准单据的增删改查需求。
*   **反例：** 不要迷信低代码。当涉及极度非标的 3D 交互、超高性能实时计算场景时，过度依赖框架的自动化渲染可能会遇到瓶颈。

**具体例子：**

创建 `P-BOM` 后，你通常不用先写“新增 BOM”“编辑 BOM”“删除 BOM”“BOM 列表页”这些基础代码。Frappe 会给你一个后台表单、一个列表页和基础 API。你应该把精力放在业务规则上，比如“BOM 明细不能重复物料”“ECO 发布后 BOM 要升版”。

**初学者提醒：**

低代码不是不用代码，而是少写重复代码。真正有价值的代码，是表达业务规则的代码。

## 第二阶段：核心构造块的深层原理 (Deep Dive into Blocks)

### 1. DocType：不只是表，是业务实体
*   **建模深度：** 善用 `Link`（引用）和 `Table`（明细）。
*   **注意：** 避免在单个 DocType 中设计过多字段（超过 100 个），这会显著降低 MariaDB 的查询性能和 UI 加载速度。对于海量数据下经常参与过滤、排序或关联查询的字段，应在字段配置中评估启用 `db_index`，但不要给低选择性字段盲目加索引。

**具体例子：**

`P-BOM` 是主表，表示“一份 BOM”。`P-BOM Item` 是子表，表示“这份 BOM 里有哪些物料”。`P-BOM` 通过 Table 字段包含多行 `P-BOM Item`。

如果把 BOM 想象成一张纸质表单，表头是成品物料、版本、状态，下面的表格就是多个子项物料和数量。Frappe 的主子表就是把这张纸质表单数字化。

**字段选择小抄：**

| 需求 | 推荐字段类型 |
| --- | --- |
| 输入一段短文字 | Data |
| 输入较长说明 | Small Text |
| 从固定选项中选择 | Select |
| 选择另一张业务表里的数据 | Link |
| 上传文件 | Attach |
| 在主表里放多行明细 | Table |
| 输入日期 | Date |
| 输入数量、金额 | Float 或 Currency |

### 2. 后端逻辑：Controller 与 Domain 拆分
*   **传统做法：** 把逻辑全塞进 Controller 钩子。
*   **工程化建议：** 对于简单的业务校验，放在 Controller 钩子（如 `validate`）是高效的。但对于跨单据、跨领域的复杂逻辑，应遵循“瘦 Controller，厚 Domain”的原则，将逻辑拆分到独立的 `service.py` 或 `utils.py` 中，Controller 仅作为入口调用。

**具体例子：**

保存 BOM 前检查“明细数量必须大于 0”，适合放在 `P-BOM.validate` 里。因为这是这个单据自己的基础规则。

但“ECO 发布后要复制旧 BOM、生成新版本、通知质量部门、同步 MES 系统”就属于更复杂的跨单据流程。此时可以让 `P-ECO.on_submit` 只负责调用服务函数，例如 `apply_eco_revision(self)`，具体细节放到独立模块。

**初学者判断方法：**

如果一句话能说清楚，而且只影响当前单据，可以先放 Controller。如果牵涉多个单据、多个系统或很多步骤，就要考虑拆出去。

## 第三阶段：复杂业务模式与安全边界

### 1. 权限模型的真相
*   **权限分层：** Role Permission 是粗粒度的，User Permission 是行级的，Perm Level 是字段级的。
*   **安全风险：** 框架的自动权限拦截主要发生在 `frappe.get_list` 或标准 UI 路径下。如果你在后端直接使用 `frappe.db.sql` 或 `frappe.db.get_all(..., ignore_permissions=True)`，你需要自己负责数据的越权检查。

**具体例子：**

普通工程师可以创建 BOM 草稿，但不能提交 BOM。工程经理可以提交 BOM。质量人员只能查看已审核 BOM。这就是角色权限。

如果将来系统按工厂分数据，例如上海工厂的人只能看上海工厂的 BOM，北京工厂的人只能看北京工厂的 BOM，这就是行级权限或数据范围问题。

**初学者提醒：**

权限不是“页面上隐藏按钮”这么简单。真正的权限要保证用户即使通过 API 或报表，也不能看到不该看的数据。

### 2. 工作流 (Workflow) 与 BPMN 的界限
*   **适用场景：** Frappe Workflow 非常适合单据的状态流转、权限锁定和简单审批。
*   **不适用场景：** 如果你的业务涉及复杂的跨系统补偿事务、高并发流程仿真、或者需要遵循 BPMN 2.0 标准的复杂流程编排，Frappe 内置的工作流可能略显单薄，此时应考虑作为“轻量级审批流”使用。

**具体例子：**

ECO 的流程可以设计为：

1. 工程师创建草稿。
2. 工程师提交到审核中。
3. 工程经理批准发布。
4. 发布后单据只读，BOM 自动升版。

这类状态清晰、动作明确、角色不复杂的流程，非常适合 Frappe Workflow。

## 第四阶段：现代化集成与部署 (Integration & DevOps)

### 1. 无缝 API 与 Webhooks
*   **API 生产力：** 每个 DocType 默认暴露的 REST API 是 Frappe 作为“无头”后端的基础。
*   **Webhooks：** 掌握事件驱动开发，减少轮询，提升系统响应速度。

**具体例子：**

外部 MES 系统想读取物料列表，可以请求 `/api/resource/P-Item`。如果企业微信机器人想在 ECO 发布后收到通知，可以配置 Webhook，在单据提交或状态变化时推送消息。

**初学者提醒：**

API 给系统调用，报表给人查看。不要把报表当成长期稳定的系统接口。

### 2. Bench 治理
*   **开发与生产差异：** 理解 `bench start` (开发环境) 与 `bench setup production` (使用 Nginx/Supervisor/Gunicorn) 的区别。
*   **队列隔离意识：** 在多 Site 或高并发场景下，后台任务会通过 RQ/Redis 执行。架构师需要关注不同 Site、不同队列（short/default/long）之间的资源隔离、Worker 数量配置和任务积压监控，否则异步任务会成为系统吞吐的下一个瓶颈。

**具体例子：**

开发时你可以用 `bench start` 同时启动 Web、Worker、Scheduler。生产环境不能这么随意，需要让 Nginx 接收请求，Gunicorn 运行 Web 服务，Supervisor 管理进程，Redis/RQ 处理后台任务。

如果某个 Site 大量导入 BOM，后台长任务可能占满 Worker，导致另一个 Site 的邮件、通知或报表任务变慢。这就是为什么高阶团队要关心队列隔离。

## 第五阶段：AI 时代的价值迁移

*   **从“怎么写”到“写什么”：** AI 能帮你生成符合 Frappe 规范的代码块，但它不知道你的 BOM 逻辑是否符合行业标准。
*   **Custom App 隔离原则：** 为了保持系统的可升级性，**永远不要直接修改标准 DocType 或代码**。务必通过 `Custom App` + `Property Setter` + `Hooks` 实现定制。这是区分初级和高级 Frappe 开发者的关键指标。

**具体例子：**

你可以让 AI 帮你写“检查 BOM 子项不能重复”的 Python 代码，但你必须告诉 AI 什么叫重复、重复时提示什么、是否按物料编号判断、是否要考虑替代料。这些业务判断来自你对企业流程的理解。

**本课程最终希望你获得的能力：**

不是背 API，而是看到一个真实业务问题时，能判断应该建哪些 DocType、字段怎么设计、哪些逻辑放 Controller、哪些流程用 Workflow、哪些数据用 Report 或 API 暴露。
