# 讲师手册

## 0. 本版本授课原则

`frappe2` 面向基础更薄弱的学员，讲师不要默认大家理解 ERP、数据库、权限和 API。每讲一个新概念，都建议按这个顺序展开：

1. 先讲业务场景：企业里为什么需要它。
2. 再讲 Frappe 名词：这个能力在 Frappe 里叫什么。
3. 再演示界面入口：从哪里点进去。
4. 最后才展示代码或配置。

课堂节奏上，宁可少讲一点架构，也要确保学员能独立完成一条完整业务流程。

## 1. 建议课时

适合 3 天训练营或 6 次半天工作坊。如果学员有 ERP 或 Python 基础，也可以压缩为 2 天。

| 模块 | 建议时长 | 目标 |
| --- | --- | --- |
| 基础导学与项目规格 | 90 分钟 | 解释术语、角色、业务对象和示例数据 |
| 讲义讲解 | 120 分钟 | 理解 DocType、权限、Workflow、Report、API |
| 实验一 | 150 分钟 | 慢速完成 DocType 建模和数据录入 |
| 实验二 | 120 分钟 | 完成后端校验与前端联动 |
| 实验三至四 | 180 分钟 | 完成权限、Workflow 与 ECO 升版 |
| 实验五至六 | 150 分钟 | 完成报表和 API 集成 |
| 实验七与结课演示 | 120 分钟 | 完成测试、fixtures、交付清单 |
| 结课演示与点评 | 60 分钟 | 按 Rubric 验收最终项目 |

## 2. 讲解重点

- 对基础学员，先不要讲太多源码结构，先让他们理解 DocType 和字段。
- 先讲业务对象，再讲 DocType。
- 强调 Link 与 Table 是 ERP 建模的核心组合。
- 权限章节必须演示普通用户和经理用户的差异。
- ECO 升版逻辑要让学员意识到：跨单据联动是业务架构能力，不只是写代码。
- 报表和 API 部分要提醒权限、安全和参数绑定。
- 最后用 fixtures 和测试把课程拉回工程化交付。

## 3. 常见卡点

| 问题 | 处理方式 |
| --- | --- |
| 分不清 DocType 和 Document | 用“表单模板”和“一张具体表单”来解释 |
| 分不清 Link 和 Table | Link 是选择一条已有数据，Table 是在当前表单里放多行明细 |
| 不知道从哪里进入配置 | 统一训练使用顶部搜索框进入 DocType、Role、Workflow、Report |
| `bench start` 启动失败 | 检查 Redis、MariaDB、端口占用和虚拟环境 |
| 浏览器打不开 `test.localhost` | 检查 hosts、端口和站点是否创建成功 |
| DocType 字段不显示 | 执行 clear cache，确认字段保存并刷新页面 |
| Controller 不生效 | 检查 Python 类名、模块路径、DocType 是否勾选 Is Submittable |
| Workflow 状态不变 | 检查 Workflow State 字段名和 Transition 权限 |
| API 返回 401 | 检查 `Authorization: token key:secret` 格式 |
| 报表 SQL 失败 | 检查表名是否为 `tabDocType Name`，参数是否配置 |

## 4. 课堂提问

- `P-Item` 是 DocType，`MAT-SCREW-001` 是什么？
- BOM 表头和 BOM 明细为什么要拆成两个 DocType？
- 为什么 BOM 子项适合用 Table，而不是单独写一个普通 DocType 页面？
- 已审核 BOM 为什么不应该被普通工程师直接修改？
- `frappe.get_list` 和 `frappe.db.sql` 在权限上有什么差异？
- 如果 ECO 发布后发现目标版本填错，系统应该允许直接修改还是走反向变更？
- 哪些配置必须通过 fixtures 进入代码库？

## 5. 演示建议

- 每次演示只引入一个新概念，例如先只讲 Link，不要同时讲 Fetch From、权限和脚本。
- 每个实验结束时，让学员用自己的话解释“我刚才建了什么业务对象”。
- 每个实验先演示“业务场景”，再演示“Frappe 实现”。
- 每次写代码后都在 UI 中制造一个失败案例，例如重复物料、负数数量、无权限提交。
- 最后让学员用普通用户账号完成一次完整流程，再用经理账号发布 ECO。

## 6. 备用方案

如果现场环境大面积失败，讲师应准备：

- 一个已完成实验一至三的备用站点。
- 一组截图，展示 DocType、Workflow、Role Permission 和 Query Report 配置。
- 一份预置 API Key/Secret，用于演示 API 调用。
- 一份包含错误代码的样例，用于讲解调试方法。
